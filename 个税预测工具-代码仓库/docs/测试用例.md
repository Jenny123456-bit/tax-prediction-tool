# 测试用例说明

> 本文档与 `tests/` 目录下的代码一一对应。33 条用例全部可执行，运行 `npm test` 约 0.34 秒完成。
> 用例编号规则：`EN-` 引擎单测、`AC-` 验收用例、`SM-` 静态契约。

## 1. 测试概览

| 层次 | 文件 | 用例数 | 目标 |
|---|---|---|---|
| 引擎单测 | `tests/engine.test.js` | 16 | 锁定税法口径：税率档、盲区、预扣、诊断 |
| 验收用例 | `tests/acceptance.test.js` | 8 | 对应 PRD 第 8.1 节，期望值精确到元 |
| 静态契约 | `tests/smoke.test.js` | 9 | 锁定页面结构、资源路径、零外部依赖 |
| **合计** | | **33** | |

### 运行方式

```bash
npm test                      # 全部 33 条
npm run test:engine           # 仅引擎单测
node --test tests/engine.test.js   # 单文件
```

环境要求：Node.js ≥ 18，**无需 `npm install`**（零依赖）。

预期输出：

```
# tests 33
# pass 33
# fail 0
```

### 引擎如何被测试

`tax-engine.js` 是挂载到 `window` 的 IIFE，本身不依赖浏览器。测试用 Node `vm` 沙箱加载：

```js
const sandbox = { window: {} };
vm.createContext(sandbox);
vm.runInContext(code, sandbox, { filename: 'tax-engine.js' });
const E = sandbox.window.TaxEngine;
```

因此不需要 jsdom，也不需要为测试改造生产代码。

## 2. 引擎单测（EN）

基准参数 `BASE`：月薪 20,000 / 年终奖 60,000 / 社保 2,100 / 公积金 2,400 / 无专项附加。

| 编号 | 用例名 | 输入 | 期望 |
|---|---|---|---|
| EN-01 | 综合所得：七档税率表的区间边界逐一校验 | `annualTax(x)` | 0→0；36,000→1,080；36,001→1,080.1；144,000→11,880；300,000→43,080；420,000→73,080；660,000→145,080；960,000→250,080；1,000,000→268,080 |
| EN-02 | 综合所得：负值与非数字输入不产生负税额 | `-1000`、`NaN` | 均返回 0 |
| EN-03 | 年终奖单独计税：按月换算定档，按全额计税 | `bonusTaxEach` | 36,000→1,080；36,001→3,390.1；144,000→14,190；150,000→28,590；0→0 |
| EN-04 | 年终奖盲区：六个区间的上下界与官方口径一致 | `BLIND_ZONES` | 36,000–38,566.67；144,000–160,500；300,000–318,333.33；420,000–447,500；660,000–706,538.46；960,000–1,120,000（误差 ≤ 0.01 元） |
| EN-05 | 年终奖盲区：区间内命中、区间外不命中 | bonus = 38,000 / 38,600 / 150,000 / 60,000 | 命中 / 不命中 / 命中 / 不命中 |
| EN-06 | 年终奖盲区：调整到下限后税后收入确实更高 | 150,000 → 144,000 | 税后损失 8,400 元，且与 `bonus − tax` 自洽 |
| EN-07 | 自动择优：两种计税方式中取税额较小者 | BASE | 单独 15,870；并入 20,280；选「单独」，最终个税 15,870 |
| EN-08 | 自动择优：高收入场景下并入更优 | 月薪 35,000 + 奖金 150,000 + 全套扣除 | 并入 38,180；单独 38,620；选「并入」 |
| EN-09 | 累计预扣法：逐月税额合计等于全年综合所得税额 | BASE | Σ12 月税额 = 综合税 10,080 + 奖金税 5,790 = 15,870 |
| EN-10 | 累计预扣法：无年终奖时逐月税额合计等于全年税额 | bonus = 0 | Σ = 全年税额；汇算差额 = 0 |
| EN-11 | 累计预扣法：下半年月度税额不高于上半年 | BASE | 上半年合计 3,780 < 下半年合计 6,300 |
| EN-12 | 仅年度汇算扣除项：产生可退税差额 | `addAnnual = 20,000` | 汇算可退 2,000 元（10% 档） |
| EN-13 | 税后年收入 = 总收入 − 三险一金 − 个税 | BASE | 230,130；月均 = 230,130 / 12 = 19,177.5 |
| EN-14 | 节税额必须用精确期权衡 | `savingOf(150000, 10000)` | 精确 1,600 ≠ 朴素 2,000，且精确值更小（跨档：6,000 按 20%、4,000 按 10%） |
| EN-15 | 诊断：未申报任何专项附加时给出缺口语义 | 全部扣除开关为 false | 建议 ≥ 4 条，含 housing / elderly / child；「年终奖择优」标记 `realized` 不计入汇总 |
| EN-16 | 诊断：全部扣除已申报时不再提示缺口 | 全部开关为 true 且公积金 12% | 可执行建议数 = 0 |

## 4. 静态契约（SM）

这些用例锁的是「页面结构一旦被改动导致功能静默失效」这类回归。

| 编号 | 用例名 | 断言要点 |
|---|---|---|
| SM-01 | 页面包含全部关键元素 | 61 个 id 全部存在（输入控件、结果区块、AI 浮窗、设置弹窗） |
| SM-02 | 脚本按依赖顺序加载 | 严格为 `tax-engine.js` → `app.js` → `chat.js` |
| SM-03 | 所有本地资源文件真实存在 | 页面引用的 css / js 均在磁盘上可找到 |
| SM-04 | 零外部依赖：不加载任何 CDN 资源 | 不存在 `src="http…"` / `href="http…"` |
| SM-05 | 法定扣除上限写在输入控件上 | pension 12000、healthIns 2400、medicalAmount 80000、elderlyShare 1500 |
| SM-06 | hidden 属性必须强制生效 | CSS 中存在 `[hidden]{display:none!important}`（否则弹窗永远显示） |
| SM-07 | 样式包含响应式与打印适配断点 | 存在 `max-width:1120px`、`max-width:720px`、`@media print` |
| SM-08 | 页面声明了移动端视口 | `width=device-width` |
| SM-09 | 答辩与合规所需的说明文案存在 | 年终奖优惠截止日、免责声明、「不会上传到任何服务器」 |

## 5. 手工验收清单（部署后执行）

自动化测试无法覆盖浏览器渲染与真实交互，部署完成后按 `DEPLOY.md` 的 8 项清单人工过一遍：

| # | 检查项 | 期望 |
|---|---|---|
| 1 | 打开首页 | 显示「个税预测 2027」，左右两栏均有内容 |
| 2 | 默认结果数值 | 主数字 `¥15,870`（对应 AC-01 参数） |
| 3 | 样式是否加载 | 卡片有圆角阴影、主视觉深蓝渐变；白底裸样式 = CSS 404 |
| 4 | 交互是否生效 | 月薪改 40,000，右侧实时变化；不变 = JS 404 或报错 |
| 5 | 专项附加扣除 | 打开「子女教育」→ 出现子选项，金额变 ¥2,000 |
| 6 | 图表 | 月度现金流渲染 12 根柱，悬停显示明细 |
| 7 | AI 助手 | 点气泡 → 发送「年终奖怎么发最省税」→ 返回带金额的回答 |
| 8 | 分享链接 | 点「分享方案」→ 新标签打开 → 参数完全还原 |

## 6. 持续集成

`.github/workflows/ci.yml` 在每次 push / PR 时于 **Node 18 / 20 / 22** 三个版本上跑同一套测试，并附带静态资源存在性检查。由于零依赖，CI 中不需要 `npm install`，整条流水线约 20 秒。

## 7. 未覆盖范围（如实说明）

| 未覆盖 | 原因 | 补偿手段 |
|---|---|---|
| 浏览器渲染与交互的自动化 | 未引入 jsdom / Playwright，以保持零依赖 | 开发期用无头浏览器截图 + DOM 转储人工核对；部署后 8 项手工清单 |
| AI 接口真实调用 | 需要真实 API Key，不适合放进 CI | 提供「测试连接」按钮做手工验证；接口失败有本地兜底 |
| 打印样式的像素级效果 | 无 PDF 渲染断言工具 | 人工打印预览检查 |
| 极端并发/性能 | 纯前端无服务端，不存在并发场景 | 单次重算实测 < 6ms |

> 注：本套测试的目标不是覆盖率数字，而是把「税法口径」变成可执行断言——任何人改动税率表或算法，都会在 0.34 秒内被 33 条断言拦住。
