## 1. 背景与目标

### 1.1 背景

个人所得税采用**累计预扣预缴 + 年度汇算清缴**的双层机制，普通员工在三个环节上普遍存在认知盲区：

1. **看不懂工资条**——下半年到手金额逐月下降，误以为公司少发工资，实为累计预扣法下累计应纳税所得额升档所致；
2. **算不清年终奖**——全年一次性奖金可"单独计税"也可"并入综合所得"，两者差额可达数千至数万元，且存在"多发一元、税后更少"的税率跳档盲区；
3. **用不足扣除项**——专项附加扣除 6 项 + 个人养老金等，漏报一项每年就是几百到几千元的损失，而多数人不知道该报什么、能省多少。

### 1.2 产品目标

| 目标 | 衡量指标 |
| --- | --- |
| 让用户在 1 分钟内得到全年个税与到手收入的准确预测 | 首屏即出结果（含示例数据），完成一次完整测算的交互步数 ≤ 8 |
| 把"漏报的扣除项"变成可执行的待办 | 诊断引擎覆盖 ≥ 10 类扣除缺口，每项给出预计可节税金额 |
| 消除年终奖计税方式的选择困难 | 自动对比两种计税方案并标注最优，同时对盲区主动预警 |
| 计算结果可解释、可核对 | 每个结果都能在"测算明细"中逐项回溯到公式 |
| 结果可协作流转 | 完整参数可编码为链接分享，对方打开即还原同一套测算 |

### 1.3 非目标（本期不做）

- 不做纳税申报、不做个税 APP 代办、不接入税务系统接口；
- 不覆盖经营所得、财产租赁/转让所得、利息股息红利、偶然所得；
- 不覆盖股权激励单独计税、企业年金/职业年金、解除劳动关系一次性补偿、外籍人员八项补贴等特殊计税场景；
- 不做多人协同编辑、不做账号体系（无登录、无服务端存储）。

## 2. 用户与场景

### 2.1 目标用户

| 画像 | 特征 | 核心诉求 |
| --- | --- | --- |
| 一线/新一线城市白领 | 月薪 1.5–5 万，有年终奖，有房贷或租房 | 今年到底要交多少税？年终奖怎么发更划算？ |
| 已婚有娃家庭 | 子女教育、婴幼儿照护、赡养老人多项可扣 | 我是不是还有项没报？ |
| HR / 薪酬专员 | 需要给员工解释工资条、做发放方案 | 快速试算不同发放结构的税负差异 |
| 跨年规划者 | 关心次年预算与到手现金流 | 明年每月大概能拿多少？ |

### 2.2 核心场景（Jobs To Be Done）

1. **「我这个月怎么少了两千？」** —— 查看月度到手曲线，理解税负随累计所得升档的规律。
2. **「年终奖 15 万，单独算还是合并算？」** —— 一键对比两种方案，同时看到是否踩进盲区。
3. **「我还能少交多少？」** —— 读取扣除缺口诊断列表，按可节税额从高到低逐项补齐。
4. **「帮我算算同事的情况」** —— 改几个数字即时刷新，或把参数编码成链接发给对方。
5. **「为什么是这个数？」** —— 追问 AI 助手，回答会带上当前全部测算数字。

## 3. 产品形态与技术架构

### 3.1 形态约束

| 约束 | 说明 |
| --- | --- |
| 纯静态 | 仅 HTML/CSS/JS，无 SSR、无数据库、无运行时依赖，可直接托管在任意静态服务器 |
| 零安装 | 无构建步骤，浏览器打开即用；断网可用（除 AI 助手需联网） |
| 移动可用 | ≥360px 宽度可正常操作，关键信息不横向滚动 |
| 隐私优先 | 全部收入数据仅在浏览器内存中处理，不上传任何服务器；AI Key 仅存本地 |

### 3.2 目录结构

```
tax-tool/
├── index.html                      # 单页结构：顶栏 / 输入区 / 结果区 / AI 浮窗 / 设置弹窗
└── assets/
    ├── css/style.css               # 全部样式（含响应式与打印样式）
    └── js/
        ├── tax-engine.js           # 计税引擎 + 扣除诊断（无 DOM 依赖，可单测）
        ├── app.js                  # 表单读取、渲染、交互、URL 状态
        └── chat.js                 # AI 助手：本地规则引擎 + OpenAI 兼容 API
```

### 3.3 模块职责

| 模块 | 职责 | 对外接口 |
| --- | --- | --- |
| `tax-engine.js` | 税率表、年终奖计税、累计预扣逐月模拟、汇算差额、盲区检测、诊断规则 | `window.TaxEngine` |
| `app.js` | 输入采集与校验、结果渲染、图表、分享/重置/复制、年度切换 | `window.TaxApp` |
| `chat.js` | 会话管理、上下文注入、意图识别（本地模式）、SSE 流式解析（API 模式）、配置持久化 | `window.TaxChat` |

### 3.4 数据流

```
表单输入 ──▶ readInputs() ──▶ params ──▶ TaxEngine.compute() ──▶ result
                    │                                              │
                    └──▶ ctx（明细与开关状态）──▶ TaxEngine.diagnose() ──▶ advice[]
                                                                   │
                                        result + advice ──▶ render() ──▶ DOM

                                                    window.__TAX_STATE__ ──▶ chat 上下文
```

## 4. 功能需求

### 4.1 收入输入（FR-01）

| 编号 | 需求 | 规则 |
| --- | --- | --- |
| FR-01-1 | 月薪（税前） | 数值 ≥ 0，步进 500，默认 20000；作为全年工资薪金 = 月薪 × 12 |
| FR-01-2 | 年终奖（全年一次性奖金） | 数值 ≥ 0，步进 1000，默认 60000 |
| FR-01-3 | 其他综合所得 | 数值 ≥ 0，默认 0；填写口径为**收入额**（劳务报酬按 80%、稿酬按 56% 自行折算后的金额），页面给出提示 |
| FR-01-4 | 联动 | 修改月薪时，若社保/公积金基数未被用户手工修改过，则自动同步为新月薪；手工修改后加锁，不再联动 |

### 4.2 五险一金（FR-02）

| 编号 | 需求 | 规则 |
| --- | --- | --- |
| FR-02-1 | 社保缴费基数 + 个人合计费率 | 默认基数 = 月薪，费率默认 10.5%（养老 8% + 医疗 2% + 失业 0.5%），可改 0–100 |
| FR-02-2 | 公积金缴存基数 + 缴存比例 | 基数默认 = 月薪；比例下拉 5%–12%，默认 12% |
| FR-02-3 | 每月个人缴纳合计 | 实时展示 = 社保基数 × 费率 + 公积金基数 × 比例 |
| FR-02-4 | 年度扣除 | 三险一金全年 = 每月合计 × 12，全额税前扣除 |

### 4.3 专项附加扣除（FR-03）

每项采用「开关 + 子控件 + 实时金额」的三段式行布局，开启后才展示子控件，右侧实时显示该项月扣除额。

| 项目 | 标准 | 输入方式 |
| --- | --- | --- |
| 子女教育 | 2000 元/月/每个子女 | 子女数（1–3）× 扣除比例（本人 100% / 夫妻各 50%） |
| 3 岁以下婴幼儿照护 | 2000 元/月/每个婴幼儿 | 人数（1–2）× 扣除比例（100% / 50%） |
| 继续教育 | 学历 400 元/月（同一学历最长 48 个月）；职业资格 3600 元/年（取得证书当年一次性） | 类型下拉选择，证书类显示「¥3,600/年」 |
| 住房贷款利息 / 住房租金 | 房贷 1000 元/月（最长 240 个月）；租金 1500 / 1100 / 800 元/月（按城市档位） | 四选一下拉，二者互斥 |
| 赡养老人 | 独生子女 3000 元/月；非独生子女分摊每人 ≤1500 元/月 | 类型下拉；分摊时出现金额输入（0–1500，超出自动截断） |
| 大病医疗 | 医保目录内自付累计超 15000 元部分，80000 元限额内据实扣除 | 年度金额输入（0–80000），标注"汇算扣除" |

**关键规则**：按月申报项（前 5 项中的月度部分）进入月度预扣模拟；证书类 3600 元与大病医疗为**年度汇算口径**，不计入月度预扣，由此产生的差额体现在"预计汇算可退税"。

### 4.4 其他扣除（FR-04）

| 项目 | 限额 | 说明 |
| --- | --- | --- |
| 个人养老金 | 12000 元/年 | 超过上限自动截断；提示领取时按 3% 单独计税 |
| 商业健康险 | 2400 元/年 | 超过上限自动截断 |

### 4.5 年终奖计税方式（FR-05）

| 编号 | 需求 | 规则 |
| --- | --- | --- |
| FR-05-1 | 三选一 | 自动择优（默认）/ 单独计税 / 并入综合所得 |
| FR-05-2 | 自动择优 | 分别计算两种方案全年合计税额，取较小者，差额写入结果区 |
| FR-05-3 | 盲区预警 | 年终奖落入任一税率跳档盲区时，升级为红色「风险」级提示，并给出建议发放额 |

### 4.6 结果面板（FR-06）

| 区块 | 内容 |
| --- | --- |
| 主指标（Hero） | 全年预计个税、综合税负率、扣除项已省金额；税后年收入、月均到手 |
| 应纳税所得额与税率档 | 应纳税所得额（**随所选年终奖方案变化**：单独计税时为不含奖金的应税所得，并入时为合并后应税所得）、七档刻度条（高亮当前档）、速算扣除数、边际税率 |
| 年终奖方案对比 | 两种方案税额并排，胜出方案高亮；下方一句话结论 + 可切换说明 |
| 月度到手现金流 | 12 根堆叠柱（到手 / 个税 / 社保公积金），总额即税前月薪；悬停显示逐项金额；右下角说明年终奖处理方式或汇算差额 |
| 收入 → 扣除 → 应税 结构 | 5 行水平条形（税前总收入、三险一金、专项附加、其他扣除、基本减除费用）+ 应纳税所得额 + 全年个税 |
| 扣除缺口诊断 | 见 4.7 |
| 测算明细 | 按「收入 / 扣除项目 / 计税 / 结果」四组的分行表，可一键复制为纯文本 |

展示规则：
- 金额统一千分位、默认取整；占比与税率保留 0–1 位小数；
- 所有数值使用等宽数字（`tabular-nums`）对齐；
- 柱状图数值为 0 时不渲染色块，避免误读。

### 4.7 扣除缺口诊断（FR-07）

触发时机：任一输入变化后实时重算。排序规则：先按等级（风险 > 重点 > 提示 > 科普），同级按可节税额降序。顶部汇总「还有约 ¥X 的合规节税空间」，**不重复计入已自动优化项**。

| 规则 | 触发条件 | 节税额口径 |
| --- | --- | --- |
| 住房扣除未申报 | 房贷/租金均未勾选 | 按租金最高档 1500 元/月测算 |
| 赡养老人未申报 | 未勾选 | 按独生子女 3000 元/月 |
| 子女教育/婴幼儿未申报 | 两者均未勾选 | 按 1 个子女 2000 元/月 |
| 继续教育未使用 | 未勾选 | 按职业资格证书 3600 元/年 |
| 公积金未顶格 | 比例 < 12% | 按提至 12% 增加的扣除额 |
| 个人养老金未顶格 | < 12000 元 | 按补足至 12000 元 |
| 大病医疗未申报 | 未勾选 | 标"待测算"（需实际票据） |
| 跨档临界点 | 应税所得超出某档上限 0–30000 元 | 按扣除额刚好降至临界点 |
| 年终奖盲区 | 落在盲区区间 | 标"税后多拿"，按调整至临界点的税后差额 |
| 年终奖方式已择优 | 两方案差额 ≥1 元 | 标"已优化 / 节省 ¥X"，**不计入汇总** |
| 高边际税率提醒 | 边际税率 ≥ 30% | 科普，不给金额 |
| 社保基数偏低 | 缴费基数 < 月薪 | 按个人费率 10.5% 补足差额测算 |

节税额统一用「税额差」精算，而非「扣除额 × 边际税率」，确保跨档时数值准确：

```
savingOf(T, d) = annualTax(T) − annualTax(max(0, T − d))
```

## 5. 计税规则说明

### 5.1 核心公式

```
综合所得收入额 = 工资薪金 + 其他综合所得收入额
应纳税所得额   = 综合所得收入额 − 60,000 − 三险一金 − 专项附加扣除 − 其他扣除
综合所得应纳税额 = 应纳税所得额 × 适用税率 − 速算扣除数
```

### 5.2 综合所得年度税率表

| 级数 | 全年应纳税所得额（元） | 税率 | 速算扣除数 |
| --- | --- | --- | --- |
| 1 | ≤ 36,000 | 3% | 0 |
| 2 | 36,000 – 144,000 | 10% | 2,520 |
| 3 | 144,000 – 300,000 | 20% | 16,920 |
| 4 | 300,000 – 420,000 | 25% | 31,920 |
| 5 | 420,000 – 660,000 | 30% | 52,920 |
| 6 | 660,000 – 960,000 | 35% | 85,920 |
| 7 | > 960,000 | 45% | 181,920 |

### 5.3 全年一次性奖金

**单独计税**

```
税率档 = (奖金 ÷ 12) 所落入的月换算档
税额   = 奖金 × 该档税率 − 该档速算扣除数
```

| 奖金 ÷ 12（元） | 税率 | 速算扣除数 |
| --- | --- | --- |
| ≤ 3,000 | 3% | 0 |
| 3,000 – 12,000 | 10% | 210 |
| 12,000 – 25,000 | 20% | 1,410 |
| 25,000 – 35,000 | 25% | 2,660 |
| 35,000 – 55,000 | 30% | 4,410 |
| 55,000 – 80,000 | 35% | 7,160 |
| > 80,000 | 45% | 15,160 |

**并入综合所得**：将奖金并入综合所得收入额，重新计算应纳税所得额后按 5.2 计税。

**自动择优**：`min(单独计税合计, 并入综合合计)`，该选择在年度汇算时可自行切换。

### 5.4 「多发少得」盲区

跳档瞬间税额突变，导致加薪反而税后减少。区间上界由"税后收入相等于临界点税后收入"解出：

```
b = (afterTax(L) − qd_next) / (1 − rate_next)
```

| 盲区下限 L | 盲区上界 | 说明 |
| --- | --- | --- |
| 36,000 | 38,566.67 | 多发 2,566.67 元，税后反而更少 |
| 144,000 | 160,500.00 | |
| 300,000 | 318,333.33 | |
| 420,000 | 447,500.00 | |
| 660,000 | 706,538.46 | |
| 960,000 | 1,120,000.00 | |

### 5.5 累计预扣法（月度模拟）

```
累计应纳税所得额 = 累计收入 − 累计减除费用(5000×月数)
                 − 累计三险一金 − 累计专项附加扣除 − 累计其他扣除
本期应预扣税额   = (累计应纳税所得额 × 预扣率 − 速算扣除数) − 累计已预扣税额
```

模拟假设：月薪 12 个月等额发放；其他综合所得按 1/12/月摊入；年终奖在 12 月一次性发放（选择并入时才计入）。

### 5.6 汇算差额

```
汇算差额 = 月度预扣合计 − 全年应纳个税      （>0 可退税，<0 需补税）
```

差异来源：仅年度汇算才可扣除的项目（大病医疗、职业资格证书 3600 元）未体现在月度预扣中。

### 5.7 边界处理

- 所有金额输入统一 `Math.max(0, value)`，非数字按 0 处理；
- 应纳税所得额为负时取 0，不产生负税额；
- 各扣除项的法定上限（个人养老金 12000、商业健康险 2400、赡养分摊 1500、大病医疗 80000）在读取时截断；
- 分摊类扣除比例仅允许 50% / 100%；
- 年终奖为 0 时，方案对比区显示"未填写年终奖"，不参与比较。

## 6. 数据与接口

### 6.1 计算引擎接口

```js
// 主计算
TaxEngine.compute(params) → result

params = {
  monthlySalary: number,   // 税前月薪
  bonus: number,           // 全年一次性奖金
  otherIncome: number,     // 其他综合所得收入额
  socialMonthly: number,   // 社保个人月缴
  fundMonthly: number,     // 公积金个人月缴
  addMonthly: number,      // 专项附加扣除（按月申报部分）
  addAnnual: number,       // 专项附加扣除（仅汇算部分，如大病医疗、证书 3600）
  otherAnnual: number,     // 个人养老金 + 商业健康险
  bonusMode: 'auto' | 'separate' | 'merge'
}

// 扣除缺口诊断
TaxEngine.diagnose(ctx, result) → Array<{
  key, level: 'danger'|'high'|'mid'|'info',
  title, detail, saving, savingLabel?, realized?, basis?
}>

// 原子能力
TaxEngine.annualTax(taxable)        // 综合所得年度应纳税额
TaxEngine.bonusTaxEach(bonus)       // 年终奖单独计税税额
TaxEngine.savingOf(taxable, d)      // 增加 d 元扣除的节税额
TaxEngine.BLIND_ZONES               // 六个盲区区间
```

`result` 关键字段：`taxable`、`rate`、`quickDeduction`、`comprehensiveTax`、`bonusTax`、`totalTax`、`afterTaxAnnual`、`monthlyNetAvg`、`effectiveRate`、`marginalRate`、`months[12]`、`withheld`、`settlement`、`compare{separate,merge,best,chosen,diff}`、`blindZone`、`deduction{...}`、`gross{...}`。

### 6.2 URL 参数

| 参数 | 位置 | 用途 |
| --- | --- | --- |
| `s` | hash | Base64URL(JSON) 分享态；字段含 18 个输入项、6 个开关、`bm`（年终奖方式）、`y`（年度） |
| `chat` | query | `1` 时自动展开 AI 助手 |
| `q` | query | 预置问题，配合 `chat=1` 使用，如 `?chat=1&q=年终奖怎么发最省税` |

### 6.3 AI 接口规范

- 协议：OpenAI 兼容 `POST {base}/chat/completions`
- 请求体：`{ model, messages, temperature(0–1.5, 默认 0.4), stream: true }`
- 鉴权：`Authorization: Bearer <API Key>`
- 流式：按 `data:` 行解析 SSE，`[DONE]` 结束；兼容非流式响应（`choices[0].message.content`）
- 上下文：`system` 注入测算快照 + 6 条回答约束（简明、结合具体数字、≤220 字、标注政策依据、拒绝违法建议、不编造数字）；随后带最近 8 轮对话
- 错误处理：`Failed to fetch` → 网络/CORS 归因；`401/403` → 鉴权失败；`404` → 路径错误（提示补 `/v1`）；`429` → 限流或余额不足
- 预置服务商：DeepSeek / 通义千问 / Kimi / OpenAI，一键填充地址与模型

## 9. 已知限制与风险

| 限制 | 影响 | 后续处理 |
| --- | --- | --- |
| 未覆盖股权激励、企业年金、离职补偿、外籍补贴 | 特定人群测算偏差 | 后续以「高级扣除」折叠区扩展 |
| 社保基数未做当地上下限校验 | 高薪/低薪人群基数可能失真 | 接入社保基数上下限配置表 |
| 其他综合所得按统一 80% 口径 | 稿酬（56%）、特许权（80%）差异未区分 | 后续拆分为分类录入 |
| 月度模拟假设月薪等额 | 有调薪/补发时逐月曲线与实际不符 | 支持按月录入或年度总额 + 调薪月份 |
| 政策随年度调整 | 税率/扣除标准变更需改代码 | 将政策参数抽为配置对象并标注生效年度 |
| 分享态依赖 URL 长度 | 参数较多但仍在浏览器上限内（约 500 字符） | 无需处理 |
